# Environment notes (Termux / Android)

Things that bite agents and scripts working with the OpenCode CLI on Termux.
Read this before writing shell scripts, MCP bridges, or tool wrappers.

## Shebangs: `#!/usr/bin/env …` fails inside OpenCode

Termux keeps `#!/usr/bin/env sh` (and friends) working with
`libtermux-exec`, a **bionic** library that Termux preloads through
`LD_PRELOAD`. It rewrites the shebang interpreter path (`/usr/bin/env` →
`$PREFIX/bin/env`) at `execve()` time.

OpenCode is a **glibc** binary, so its launcher must `unset LD_PRELOAD`
before exec'ing it (otherwise the glibc loader tries to load the bionic
`libtermux-exec.so` and dies). The `unset` is inherited by every child
OpenCode spawns, and those children lose the shebang rewriting:

```
$ printf '#!/usr/bin/env sh\necho hi\n' > t.sh && chmod +x t.sh
$ ./t.sh                      # from a normal Termux shell: works
$ env -i PATH=$PREFIX/bin:/system/bin ./t.sh
sh: ./t.sh: /usr/bin/env: bad interpreter: No such file or directory
```

`/usr/bin` does not exist on Android, so the kernel cannot find the
interpreter and `execve()` returns `ENOENT`.

**Rules for scripts that run as children of OpenCode (MCP servers, tools):**

- Do **not** rely on `#!/usr/bin/env …` or `#!/bin/sh`. Android has no
  `/bin/sh` either.
- Prefer an absolute, Termux-owned interpreter:
  `#!/data/data/com.termux/files/usr/bin/bash`.
- Or spawn explicitly from the parent: use `"$PREFIX/bin/bash", "script.sh"`
  (this is what the `termux-api` MCP bridge does), or
  `$PREFIX/bin/sh -c '…'`.
- `termux-fix-shebang <file>` rewrites shebangs to absolute Termux paths, but
  it must itself be run by a process that still has `libtermux-exec`.
- `$PREFIX` is usually set in interactive sessions but **not guaranteed** in
  app-spawned processes; prefer the literal prefix or resolve it explicitly.

## The OpenCode launcher wrapper

`$PREFIX/bin/opencode` is generated by `OpenCodeInstaller` and is run by
`dash` (`$PREFIX/bin/sh` → `dash`), so it must stay POSIX. It:

- checks `$BIN` and the Termux glibc loader exist, printing a clear message
  and exiting `127` if the runtime is missing;
- compares `$HOME/.opencode/.patched` (written by Java as `<size> <mtime>`)
  with `stat -c '%s %Y'` of the binary. On mismatch — e.g. after
  `opencode upgrade` overwrote the patched binary — it runs the binary through
  the loader explicitly (`ld.so --library-path … "$BIN"`) instead of failing;
- `unset LD_PRELOAD` / `LD_LIBRARY_PATH` and sets
  `OPENCODE_DISABLE_AUTOUPDATE=1` before `exec`'ing the binary.

The ELF interpreter must point at
`$PREFIX/glibc/lib/ld-linux-aarch64.so.1`; the installer patches it with
`patchelf` and records the marker.

## Version pinning

Write a version to `$HOME/.opencode/pin` (a single `x.y.z`; anything after the
first token is ignored) to hold the CLI on an exact build, including
downgrades. Remove the file to track the
release channel again. While a pin exists the app always verifies that exact
version against the npm registry (no cached "fresh" short circuit), but it
still works offline if the installed binary already matches the pin.
